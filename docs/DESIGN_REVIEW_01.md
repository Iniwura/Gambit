# GAMBIT — Design review 01

**PROPOSED — not locked, not implementation.** No changes to the live gameplay branch or deployed contracts.

The owner requested a professional end-to-end game design review before visual implementation. A separate portable `GAMBIT-design-master-v1.zip` has been authored and delivered in the design conversation: 32 individual editable SVG artboards, PNG previews, three contact sheets, 18 standalone concept assets, source generation script, design bible, state matrix, asset inventory, and an offline artboard review navigator. The ZIP and SVG assets are delivered as conversation files, not checked into this repository or claimed as a native Figma file. The user can connect Figma for native editable design collaboration.

## Proposed art direction
Reactor field manual: original stylized armored operators, fixed isometric industrial reactor, graphite surfaces (#10171c/#0b1115), acid-lime primary action (#d6ed8c), ally cyan (#79d0ca), opposing amber (#e7a17c), Noto Sans Display headings, Inter controls and monospaced scores. Deliberately restrained HUD, with selected-role command editor and clear focus treatment. Neutral opponent visuals do not expose hidden formation/individual lane outcomes. All pictured match values are illustrative and must never be described as live evidence.

## Review coverage
Boot, command deck, first launch, arena lobby, wallet selection, invite creation/recovery, planning, transaction review, pending receipt, waiting, resolution, KMS, round result, recovery, expiry, debrief, training and training debrief, Blacksite and Blacksite debrief, Commander, proof record, settings, pause, portrait main menu/planning/review; foundation, component, character and environment sheets. Additional state variants and full mobile coverage are listed as pending in the package matrix. Character turnarounds, sprite animation atlases, final texture/environment passes, audio files, motion keyframes, native linked Figma flows and player usability review remain unfinished. The art direction is subject to owner approval.

## Research
- [XCOM 2 UI designer case study](https://jamuidesign.com/xcom-2/) — tactical HUD restraint and iteration through playtesting.
- [Into the Breach UI design interview](https://www.gamedeveloper.com/design/-i-into-the-breach-i-dev-on-ui-design-sacrifice-cool-ideas-for-the-sake-of-clarity-every-time-) — clarity before decoration.
- [Unity UI design guide](https://unity.com/resources/user-interface-design-and-implementation-in-unity?ungated=true) — design phases and asset preparation.
- [Xbox accessibility guidelines](https://learn.microsoft.com/en-us/xbox/accessibility/guidelines) — focus, contrast, legibility, navigation, motion.
- [Figma prototyping guide](https://help.figma.com/hc/en-us/articles/360040314193-Guide-to-prototyping-in-Figma) — reviewable flows before implementation.
