# GAMBIT R05 — real-time art pipeline

The owner approved switching from slow Blender production to curated game-ready assets and a Three.js visual preview. This is approval of the production method, not approval of artwork, layouts, implementation, or any score. Preserve v001/v002 Blender sources and earlier rejected reviews; stop expensive Blender render batches. Preserve Phaser, the four-pillar roadmap, verified live Arena and all security boundaries. R01–R04 are rejected visual designs, not implementation specifications.

## Curated source candidates (free files only)

[Universal Base Characters](https://quaternius.com/packs/universalbasecharacters) as alternative only if coherent compatible costumes and animation are available without Blender.
- Props: [Sci-Fi Essentials Kit](https://quaternius.com/packs/scifiessentialskit) free subset; use selectively.
- Verify archive license and rights for each used asset, including modifications and redistribution, before importing. Record source URL, actual version/archive SHA256, license text, selected filenames, material/texture provenance and modifications in manifest. No paid packs, subscriptions, copied game art, external runtime asset hotlinks, or secret material. Do not download large unrelated packs. Do not claim source art is original.

## First deliverable: one exceptional browser-rendered arena, NOT 45 wireframes
1. Find and preserve local art outputs. Use an isolated clean checkout or new directory adjacent to existing work. Read this file and the approved reference benchmarks. Do not resurrect the rejected R04 layout. Existing R03 world/role intent is reference only, not locked visual decisions.
2. Download official free assets. Inspect GLB/glTF scenes, geometry, materials, textures and actual skeletal clips. Make contact sheets of real candidate characters and modular environment pieces. Reject models that look too generic, primitive, inconsistent or unreadable. Choose one coherent family. If no suitable characters, report the exact gap rather than fallback to primitive robots.
3. Compose a real-time art sandbox (separate from production game) with pinned Three.js version and reproducible local dependencies. GLTFLoader loads local assets; clone rigged units correctly and use AnimationMixer for real clips. One orthographic 3/4 camera, intentional cutaway orbital reactor room, three readable sectors, six staged units. Low front walls, rear machinery, catwalk framing, meaningful architecture and material separation. Broad neutral key, warm practical accents, soft contact shadows, controlled highlights, consistent art scale. Keep scenery visually quieter than units. Design role silhouettes through actual equipment/costume and model choices, not color alone. No generic floating platform, neon overload, or placeholder shapes as finished art.
4. Add a single game-first interface composition around real assets. World-space own-unit selection and compact contextual orders; fast editing for experienced players; optional teaching steps, never forced nine-step wizard. Actual Strike/Guard/Flank opening, trigger and response; Hold/Pivot/Feint; optional GAMBIT with public activation and private sector. Minimal round/score/status HUD. No fabricated movement/pathfinding, hidden rival orders, individual encrypted outcomes or automatic transactions. All preview actions clearly design-only.
5. Render actual 1920x1080 and 390px representative views using browser screenshots. Verify no missing models/textures, blank captures, clipping, or unsupported animation claims. Include short motion preview, individual operators and a clean plate. Compare to Tactical Breach Wizards (primary), Gears Tactics (aspirational atmosphere), XCOM: Chimera Squad (characters), Into the Breach (clarity). Measure performance on available hardware; target 60fps desktop, 30fps mobile, no claim without measurement. If hardware/WebGL limitation, report it and test a lightweight quality preset. Do not repeat long render batches.
6. Save source, manifest, real screenshots and reproducible launch instructions. Provide a single review ZIP and actual screenshot for owner review. Do not expand to remaining modes until arena and characters meet visual gate. Afterwards apply approved design to loader, menu/HQ, lobby/invitations, arena plan/review/wait/result/recovery, Academy, Blacksite, Commander, settings, responsive and audio/motion states. Show authentic public data only when verified. Design remains unlocked until owner approval.

## Integration decision, after approval
Prefer exporting transparent sprites/animation atlases and static scene plates to existing Phaser presentation, or a thin isolated Three.js scene renderer behind existing controllers only if measured performance and maintainability justify it. Do not ship two competing gameplay engines, migrate game rules, or rewrite contract/wallet/SDK/proof logic. No production integration, merges, signing, new deployments, purchases, or automated retries authorized. Quality assessment must be on actual complete artifact, not number of assets or test count. Do not claim 90+ or winning chances without evidence.

Official APIs: https://threejs.org/docs/pages/GLTFLoader.html and https://threejs.org/manual/pages/animation-system.html.
